# Evidence for the decision record

Outputs of the November 2026 evidence workflow behind ../../02-decisions.md. Six research agents each answered a group of open questions in a report, using literature, documentation, source code and their own experiments. One adversarial verifier per report reran experiments, checked claims and gave a verdict on every reference (66 of the 146 reference verdicts in `reports.json` are 'unverifiable'). Not every experiment was rerun. A consistency critic then reviewed the decisions together and found conflicts between them, which the decision record resolves in the decisions concerned and in its cross-cutting conventions.

`reports.json` holds the six research reports and the six verification verdicts. The reports are keyed `research:python-engines`, `research:re-structure`, `research:scope-reports`, `research:packaging-names-licence`, `research:declarations-data` and `research:paper-hpc`, for folders A to F in that order, and each verdict has the matching `verify:` key. The critic's findings are in `G-critic/out/G_inconsistencies.csv`.

Where a verifier or the critic corrected a report, the decision record adopts the correction. Where the critic resolved a conflict differently from a verifier, the record follows the critic, as in finding G19 on PNG copies. Tables and scripts keep each report's proposals as they stood, and where they differ from the decision record, the record prevails. For example, `F/tables/validation_protocol.csv` lists V4 and V6 under v1.0 and proposes a 1,536-row cap on the H1 grid. The decision record drops the cap and schedules V6 after 1.0, and V4 after 1.0 unless 1.0 reports variance-component tests.

R results came from Ubuntu 24.04's R 4.3.3 with lme4 1.1-35.1 and glmmTMB 1.1.8, which predate lme4 2.x and glmmTMB 1.1.9 to 1.1.15. Behaviour of current versions was checked from source only. Python versions are recorded only where a report noted them. Report E used Python 3.13.18 with numpy 2.5.4, pandas 3.1.1, jsonschema 4.26.0, rfc8785 0.1.4 and PyYAML 6.0.3 (`E/out/versions.txt`, which also lists its R packages). Its verifier also used fastjsonschema 2.22.3 (`E-verify/out/schema_probe.tsv`). The benchmark's engine versions (statsmodels 0.15.0, glmm 0.8.0, mixedlm 1.3.0, gpboost 1.8.0 and rpy2 3.5.17) are in `A/bench/comparison_rows.json`, and its R session is in `A/bench/r_reference.json`. The A-verify virtual environment used Python 3.12.

CRAN, R-universe, publisher sites, doi.org and Crossref were unreachable, and the web-search budget ran out during verification, so many references in these files are unverified. Only references listed in ../../02-decisions.md were confirmed for that document.

Bibliographic checks made after the evidence was frozen settle three entries that `A-verify/out/reference_checks.csv` left open. Halekoh and Højsgaard (2014), the pbkrtest article in the Journal of Statistical Software, 59(9), https://doi.org/10.18637/jss.v059.i09, runs to pages 1–32 according to its DOAJ record and the Aalborg University portal. The range 1–30 in that file and in the verifier's corrected entry in `reports.json` comes from the package CITATION file. The values the file gives for Seabold and Perktold (2010) and Harville (1977), which it marks as unverifiable, are correct. Seabold and Perktold (2010) is on pages 92–96 of the Proceedings of the 9th Python in Science Conference, https://doi.org/10.25080/Majora-92bf1922-011. Harville (1977) is in the Journal of the American Statistical Association, 72(358), 320–338, https://doi.org/10.1080/01621459.1977.10480998, which answers the verifier's query in `reports.json` about the range 320–340.

In `reports.json`, result A-E01 of `research:python-engines` states that the Laplace values agree with glmmTMB's to 1.5e-12. That holds for two datasets only. On the crossed binary design (binxd_laplace), glmmTMB's reported value differs from the reference objective by 1.35e-8 (`A/bench/benchmark_table.csv` and `A-verify/out/check_ref_objective.txt`), as 02-decisions.md (Q1) states.

Datasets distributed with lme4 and glmmTMB were left out, because those packages are GPL- or AGPL-licensed. Lines 1 to 107 of `A/bench/r_reference.R` regenerate them from R. To show duplicated keys, `E/out/exp3_exam_duplicate_keys.txt` reproduces eight rows of the Exam data from mlmRev, a GPL (≥ 2) package whose data licence is not stated (`E/tables/q8_datasets.csv`). Email addresses have been redacted.

Absolute paths under /tmp and /home/user refer to the ephemeral environment in which the scripts ran, where `/tmp/claude-0/-home-user-lmecheck/76ff8921-f521-5c13-b469-59b514d4e510/scratchpad/r2/` was this folder. Thirteen scripts in A-verify, B, B-verify and G-critic hard-code that root, and four scripts in D and D-verify load that environment's certificate bundle, `/root/.ccr/ca-bundle.crt`. These paths need changing before the scripts run elsewhere. To rerun a script, copy this folder elsewhere first, because some scripts write into it. Among them are `A-verify/scripts/check_ref_objective.py`, `A-verify/scripts/sm_boundary.py` and, when given F/budget, `F/budget/budget.R`. Scripts that query PyPI or GitHub need network access, and the GitHub code searches in `F-verify/exp/ghsearch.py` and `F-verify/exp/ghbib.py` also need an authenticated client.

Some files are byte-identical to others. In ten cases, a verifier's rerun reproduced a report output byte for byte, and the identity is the evidence of reproduction. These reruns are `C-verify/out/news_class_counts_rerun.csv` and, in `E-verify/out`, `yaml_r_rerun.tsv`, `yaml_py_rerun.tsv`, `exp2_rerun.csv`, `zoo_table_hash_R_rerun.tsv`, `zoo_table_hash_py_rerun.tsv`, `e1_rerun/exp1_reuse_vs_crossing.csv` and the three files in `e3e4`. The identity of `E/out/table_hash_R.tsv` and `E/out/table_hash_py.tsv` is report E's cross-language parity result. The other identical files are copies or shared fixtures. `F-verify/exp/budget_sens.R` is an unchanged copy of `F/budget/budget.R`, from which `F-verify/exp/make_scenarios.py` writes the scenario variants. The two demonstration packages in `D/exp_suggests` share one licence file, and some zoo and edge-case fixtures share a `formula.txt` or `design.json`.
