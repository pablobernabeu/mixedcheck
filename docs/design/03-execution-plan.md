# Execution plan

This plan turns the decisions in 02-decisions.md into milestones for a single maintainer. Each milestone ends at a gate, a set of conditions that must hold before the next one starts, rather than at a date. Revise the plan whenever a gate exposes a problem.

Work happens in three places. Implementation runs in cloud sessions or locally. Checks that need sites blocked in the cloud sessions (CRAN, R-universe, publishers and Oxford's internal pages) run in the local session or in GitHub Actions, whose runners can install current CRAN packages. Simulation studies and every other heavy step, image builds included, run on ARC, which the local session reaches over SSH. Jobs go to the htc cluster with `sbatch --clusters=htc`, never on a login node, and large files are kept under /data/educ-intract/educ1242/.

Each component is built in R first. Rscript then writes JSON fixtures, and the Python port is developed against those fixtures. Parity is enforced at milestone gates rather than on every commit.

## M0. Foundations

The maintainer has chosen mixedcheck as the package name, subject to the registry checks (02-decisions.md, Q7), and development proceeds in the private repository. Once M0 is merged, these steps follow in order:

1. The name checks, `pak::pkg_name_check()` and an R-universe search, run as a GitHub Actions job.
2. The repository is renamed mixedcheck.
3. The repository goes public, which starts the six months of public history that JOSS requires and makes Actions minutes free for the full matrix.

The skeleton follows the layout in Q7. r/ holds a minimal R package: DESCRIPTION with Depends R ≥ 4.2.0, the two-line licence stub and testthat (02-decisions.md, Q6 and Q10). Each Import is declared when the code first uses it, because R CMD check reports an Import that the code does not use. jsonlite and cli are declared in M0, where they read and verify the vendored files, and Matrix, jsonlite, cli and utf8 are all declared by M2. python/ holds a pyproject package with a src layout, requires-python ≥ 3.11 and numpy, pandas and scipy as dependencies. Each extra is declared with its first optional dependency, because an empty extra would accept an installation request and install nothing. spec/, fixtures/, parity/, sim/ and paper/ exist with short README files. A .gitattributes file turns off Git's line-ending conversion for spec/, fixtures/ and the vendored copies, so that every checkout keeps the bytes that were hashed. Converting fixtures to LF would rewrite their deliberate CRLF cases, so LF is enforced in spec/ sources alone, by a vendoring check that rejects CR characters there. REUSE-style licence files mark any directory whose contents are not MIT, from the first fixture directory that holds third-party data. The evidence in docs/design is frozen, so its third-party material is identified in its README instead.

CI uses GitHub Actions with path filters. The R and Python workflows run the job matrix of Q10, and a vendoring workflow runs the SHA-256 check of Q7 on every vendored artefact (02-decisions.md). A minimal set of jobs runs on every push to main and every pull request, the full matrix runs nightly, and the accessibility and PDF checks run before releases. The full matrix can also be started by hand. Its nightly run starts only once the repository is public, because a private repository pays for Actions minutes and macOS minutes count tenfold. Until then, the full matrix runs on a pull request when the label 'full-ci' is added, and by hand once the workflows are on main. The M0 gate is met by such a run.

Short CONTRIBUTING, code-of-conduct, governance and succession notes give JOSS the signals of open development it looks for in single-author projects. Each release is archived on Zenodo, with a CITATION file in the repository. An organisation-owned repository would also reduce the risk of depending on one person.

## M1. Specifications

Cross-cutting conventions come first, because every reader and writer in both languages depends on them. They are recorded in docs/spec/conventions.md and cover:

- the six status fields
- the hash taxonomy and the two JSON profiles
- centring constants stored as decimal strings
- the split between the design-plan hash and the execution binding
- the disclosure_unit, event_level, trials and exposure fields
- the Unicode policy
- SHA-256 from cli in R
- RFC 8785 serialisation with ECMAScript number formatting, written in-house and tested against the RFC's vectors

One schema bundle under spec/ holds the registry entry, declaration, plan, results and estimates schemas, with shared definitions and the two profiles. The access log is a section of the results document. The declaration vocabulary 0.1 starts from the draft in evidence/decisions/E/schema, with the corrections recorded in 02-decisions.md.

A registry entry has a stable ID and version, a tier (T0, T1 or T2), the statistic and comparison exactly as computed, an assessability rule and thresholds with their sources and validation provenance. It also lists remedies, links in the dependency graph and message templates, and classifies every count it reports as a person count or a non-person count. Entries are authored in YAML, read with every scalar as a string and compiled to canonical JSON by one script under spec/tools/. The compiled JSON is the only form the packages read.

The IR specification defines how a formula and a declaration become terms, columns and grouping factors. It covers:

- the lme4 grammar the suite accepts
- contrast coding with explicit reference levels
- centring rules and constants
- the analysis sample
- factor-level order (declared levels first, otherwise code-point order after NFC)
- the rejection of `||` on factors
- the sequential rule for dropping aliased columns

Conformance corpora sit under fixtures/conformance/. They cover formula strings with their expected IR, valid and invalid documents with expected error codes, Unicode and C-locale cases and number-formatting cases. They also include the JSON and table edge cases in evidence/decisions/E/schema/edge and evidence/decisions/E-verify (edge/ and edgezoo/).

The conventions settle points that 02-decisions.md left open or that needed a narrower reading:

- 'Integers within ±2^53' is read as ±(2^53 − 1), the I-JSON range, so that every accepted integer and its neighbours are exact doubles.
- Every string and key of a document in the hashable profile must already be in NFC, and readers refuse other documents rather than normalise them, so that a hash always covers the bytes the user wrote. Identifiers and labels are still compared after NFC.
- NFC agrees across the packages only for code points assigned in Unicode 14.0, because utf8 1.2.4, the oldest release the R package accepts, implements Unicode 14.0, while Python 3.12 to 3.14 implement 15.0 to 16.0. Both packages therefore read the list of code points that Unicode 14.0 assigns (spec/unicode/assigned-14.0.json). Hashable documents refuse other code points (E1208), and identifiers and labels that hold them are compared without normalisation. Results documents record the version each package used.
- A finding that is not_available carries only availability, since nothing was computed, and optimisation is present only for checks that evaluate a fitted model (the registry's fitted_model). 02-decisions.md gives every finding six fields, and the others would only repeat that nothing was assessed.
- Decimals of magnitude below 1e-307 are refused, so that every accepted decimal maps to a normal double and back. A number whose value is integral is an integer whatever its notation, as JSON Schema compares numbers by value, so 1e21 and 1.5e300 lie outside the integer range although they have one or two significant digits. U+0000 is refused in every profile and mode, because R cannot hold it in a string.
- Exact parity (02-decisions.md, Q2) holds for error codes, canonical bytes, hashes, counts, ratios, categories, names and labels. Real statistics come from sums, determinants and eigenvalues that the two languages compute with different libraries, so they are compared within 1e-12 + 1e-9 times the larger magnitude, and a message that renders one matches by the values it renders, whatever their renderings (conventions.md, Comparison across languages), as Q5 allows for aggregates computed separately. near_threshold comes from the proximity bands of thresholds and parameters and from the bounds on rounding errors that a definition gives (registry.md, Parameters), a near_threshold finding may differ in the statuses and statistics that conventions.md names, and the optimum of the separation check is compared within bound_tolerance, as its bounds are.
- The digits of decimal constants and of messages are those of the exact binary value rounded half to even on every platform. The R package computes them in-house, because sprintf() rounds ties as the C library does, which on Windows depends on the version of the C runtime.
- R's yaml package cannot report anchors, aliases, explicit tags, merge keys or a second document, so both packages run the same pre-scan of the text before libyaml parses it. yaml 2.3.8 also reads '<<' followed by a character outside ASCII as a merge key and loses the rest of the text, so the pre-scan refuses every plain scalar that starts with '<<', and such text must be quoted. Python uses yaml.CBaseLoader, the libyaml loader that R's package also bundles, because PyYAML's pure-Python parser refuses tabs that libyaml accepts.
- Schema patterns are matched over code points in both languages, in R with PCRE in UTF mode, because R's default engine and ECMA-262 without the flag 'u' read characters outside the BMP differently.
- In the data profile, a computed non-finite double is written as the string 'NaN', 'Infinity' or '-Infinity', and null stands only for a missing value with a status object beside it.
- In R, unmarked non-ASCII strings that a caller passes in are marked as UTF-8 when the session's native encoding is UTF-8 and refused otherwise. Writers and hashers refuse unmarked strings as decided.
- R's as.numeric() does not round decimal input correctly. It misconverted 171 of 295,773 decimals of at most 15 significant digits in this project's tests, so the R reader converts numbers through a correctly rounding routine.
- Base R cannot read the operating system's random source on Windows, so the R package takes keys there from the suggested package openssl, and without it from the user (M2, and conventions.md, Keys).
- No JSON key may be empty, in either profile or without one, because R cannot tell an empty name from a missing one.
- The strict reader has a third mode without a profile, for test vectors such as the key-sorting example of RFC 8785, whose emoji key the profiles reject.

The declaration vocabulary 0.1 (docs/spec/declarations.md) reads Q4 of 02-decisions.md as follows where it left a choice:

- The rule of at least one outcome and one assigned role belongs to the minimal declaration, which a confirmatory goal, the outcome-blind and preregistration exports and the trial features require, as Q4 states. A feature 'observational' replaces the assigned role for studies in which nothing was assigned, such as secondary analyses, which the rule would otherwise exclude from confirmatory use. The trial features also require the assignment block.
- A minimal declaration also requires units, an observation key, because rows are identified by it, and at least one focal estimand, because the protected set of Q3 needs one.
- disclosure_unit is a member at the top level that names a unit of the units block, because the units block is an array of units.
- The time zone and the clock resolution of the observation time are both deferred as time-zone detail. The prediction goal and the estimand kind 'prediction' wait for the prediction goal after 1.0.
- The assignment block holds the column, the unit, randomisation, the level and the blocks, as Q4 lists them. The draft's scheme and control level are dropped, because the features, level and blocks imply the scheme and the IR sets reference levels.
- A draft from `draft_design()` lists its inferred entries as JSON Pointers in the provenance block and cannot serve as a minimal declaration until accepted, so that M3 needs no new vocabulary. Until accepted, an inferred entry counts as absent for every check, because Q4 counts a draft as a declaration only once the user accepts it. The validator checks a draft as written, so that accepting an entry cannot make a valid draft invalid.
- The table subset allows six Frictionless field types and one form per list of categories or missing values, as Frictionless v2 requires. The table reader applies fieldsMatch 'exact'.
- The Frictionless lexical defaults are written out in docs/spec/tables.md. No white space is trimmed, and missing values are matched before any conversion. NaN, INF and -INF are values rather than missing values, and a CSV file that starts with a byte-order mark is refused like any other input (E1003). The table corpus (fixtures/conformance/tables/) is built in M1 rather than with the reader in M2, so that the reader is written against expected outputs that do not come from it, as for every other corpus. The reader also checks the primary and unique keys of the table block (E5008 to E5010), since the table subset of Q4 includes them, and a column inferred as a number column without a table block reports a value out of range (E5006) rather than becoming a string column, so that the type of a column never depends on the range of its values.

The registry (docs/spec/registry.md) settles these points:

- Registry 0.1.0 also holds three assignment checks (the assignment constant within its unit, the randomisation unit in the random part and the design df) and the connectivity of crossed factors, which are not in the T0 list of M2. The prototyped zoo fixtures Z08, Z09 and Z13 expect their findings, and the M2 gate requires exact parity on the zoo.
- The T0 checks of the declared outcome in Q2 of 02-decisions.md (type, event level, trials, exposure and bounds) have no entries of their own. The declaration validator enforces the declared fields, and the T1 entries report declaration_missing for the fields they need. The warning on a single Likert item about to be modelled as metric (Q2) is left to M2, which defines how the caller states the family.
- T0 checks run on the design sample, the analysis sample before the rows with a missing outcome are removed, so that they read nothing of the outcome.
- Thresholds are decimal strings. A threshold on a ratio of counts is compared exactly in integer arithmetic, and only thresholds on real statistics have the proximity band that sets near_threshold.
- A count of the levels of a grouping factor is classified as a person count or a non-person count when the check runs, from the disclosure unit, because the same check counts schools in one design and pupils in another.
- The privacy parameters of Q5 are part of the compiled registry.
- Every threshold of registry 0.1.0 is descriptive, and every literature source is marked as not read in full until the local session reads it.
- The rule of Q9 that a descriptive flag graded consequential needs a predicted false-flag rate of at most .05 applies from registry 0.1.0, so a rule that uses a descriptive threshold grades at most detectable_inconsequential (E4020). Rules without thresholds state exact facts of the design and may grade findings consequential.
- The level at which a predictor or an assigned column varies is inferred with the 99% agreement of Q4, and findings that rest on it say so. Candidate keys, the other property that Q4 infers with tolerance, are inferred by `draft_design()` in M3, and keys.duplicates needs a declared observation key.
- The identifiability verdict for families other than Gaussian is necessary_condition_met, as in the plan, and its assessability stays adequate, since weak means reduced detection (Q9).
- Entries keep check version 1 until registry 0.1.0 is released, since versions count changes between releases. Each entry names the sample it reads, which the support of its findings counts, and each ratio names its numerator and denominator, so that the privacy filter suppresses a ratio whose counts it suppresses.

The results document, the plan and the bring-your-own estimates (docs/spec/documents.md) read Q1, Q3 and Q5 of 02-decisions.md as follows:

- The schema of the results document also describes the internal sidecar, because the keyed commitments of a results document can be verified only with the keys it holds. Sidecar version 0.1 holds the keys, the pseudonym map and the results file hash, which cannot be part of the file it covers. M5 adds the labels of predicted random effects and any observation keys that its checks write, since no check of registry 0.1.0 writes either.
- The access log records the accesses of the run that produced the document, one entry for each tier and, at T1 and T2, each outcome column read. Earlier accesses enter it only through the frozen plan's stamp and the attestation, since a log kept across runs could be rewritten by whoever holds the files (Q3). The outcome column commitment covers the column with its observation keys, its rows ordered by key, so that it does not depend on the order of the rows in the file.
- Each finding carries the counts behind it that the privacy filter needs: the rows, the distinct members of the disclosure unit, or without one the distinct levels of the grouping factors, and whether the largest contributors supply too large a share of the rows. A shareable document must meet the rules of Q5 that can be checked from the document alone, and the filter of M2 may suppress further values. Minima and maxima are quantiles 0 and 1, so the quantile rule also keeps them out of shareable output, and M2 adds the quantile probabilities to the registry's order statistics.
- The design section of a plan holds exactly what Q3 lists under the design-plan hash. The ceiling, the identifiability verdicts and the execution bindings lie outside it. A count in a plan suppressed by the privacy filter is written as `{"below": k}`, because the hashable profile has no null.
- The protected set lists components, each a grouping factor and the variables of a term of the random part, because protected intercepts and slopes sit inside correlated blocks until a rung decorrelates them. A plan's df budget is the budget of identifiability.df_budget, which is never negative, and CR2 as a terminal state needs nested grouping factors in both languages (E7309), since it clusters on one factor.
- An access is recorded as planned only after the package has checked that the run's declaration and IR belong to the plan (E7310). Checks of a tier that a run did not read yield no finding, and reports list them as not assessed.
- Contract 0.1 of the bring-your-own estimates covers the required fields of Q1 for Gaussian LMMs. A file cannot carry a function, so the capabilities objective function, refit and simulate are false in every version, and X, Z, predicted random effects and df wait for a later version.

The IR and formula grammar (docs/spec/ir.md) settle these points:

- Contrasts, reference levels and centring come from a coding argument of the IR builder, because vocabulary 0.1 has no member for them. IR 0.1 offers treatment, sum and simple contrasts, the last giving ±0.5 for two levels. Ordered categories use the same contrasts, not R's polynomial ones.
- Levels come from the declared categories or from the table as read, never from a sample, so the reference level stays fixed and a level that the design sample loses gives columns that the sequential rule drops, which sample.raw_vs_analysis then explains. R drops such levels and changes the reference silently.
- Mean centring uses the design sample, 6 significant digits by default and an exactly rounded sum, so that both languages compute the same constant. Centring within clusters is left to derived columns declared with `derived_from`.
- The grammar rejects what lme4 accepts but probably signals a mistake: removing an absent term, '- 0', duplicate random terms, a column shared by two random terms of one grouping factor and functions other than offset() and log(). Structured covariance terms give a code that names version 1.3. One-sided formulas are allowed for T0 audits.
- A declared exposure enters the IR as an offset, and the IR holds neither the formula string nor any label of a grouping factor.
- Q3 freezes the coding of factors as numeric contrast columns before the ladder is built, so the coding argument can freeze a factor, which then keeps its contrast in every term, and '||' splits a frozen factor into one uncorrelated term for each contrast column. A plan names the columns that the ceiling reads as the sample columns of every rung, so that every rung keeps the design sample and the centring constants of the ceiling.
- A column that identifies persons, by the role 'id' or as a label column of the disclosure unit, of a participant unit or of a unit nested in one, cannot be a predictor (E6068), so that IRs and plans never list the labels of persons. Other unit columns, such as schools used as blocking factors, can be. A Stream B run refuses an IR that reads an outcome, an outcome-derived column or the trials column on its right-hand side (E6069), so that the outcome-blind checks read no outcome.

The parity harness ([parity/README.md](../../parity/README.md)) and the check of references settle these points:

- The harness runs in CI on every push to main and every pull request that touches either package, spec/, fixtures/ or parity/, although the plan enforces parity at milestone gates. A run takes about 25 seconds once both packages are installed, and a mismatch found on the pull request that causes it is easier to trace than one found at a gate.
- Each outcome is compared with the expected outcome of its case as well as with the other language, so that a mistake both packages share is also caught. R runs twice, under C.UTF-8 and under the C locale, because the C-locale cases of the Unicode policy are parity cases.
- The harness also reads every vendored JSON file of spec/ through both packages and compares the canonical bytes, and the registry that both packages load must give the bytes of spec/compiled/registry.json.
- The table and formula corpora were listed in parity/corpora.json as pending until M2a implemented the table reader and the formula parser, so the M1 gate covered the corpora of what M1 implements.
- The Crossref check reads the APA references with a DOI in the Markdown files of docs/ and in the reference tables of the evidence. Differences in the frozen evidence are reported without failing the workflow, since the evidence is not edited and corrections to it are recorded in its README. A DOI that Crossref does not hold, such as the DataCite DOI of an arXiv preprint, is listed without being checked.

## M2. Stream B core

Both languages implement the same pipeline:

1. strict readers for the declaration and the data
2. canonicalisation of identifiers, missing-value tokens and level order
3. the formula parser, written in-house, with reformulas used only as a test oracle in R
4. the design matrices X and Z
5. the audits
6. the results object and its writer
7. the shared view model with its privacy filter

The T0 audits are:

- label incidence for every pair of grouping factors
- evidence on ID scope when it is undeclared
- aliased grouping factors and factors with one row per level
- within and between status with informative-group counts and predictor ICCs
- the identifiability verdict from the projected Gram matrix
- the level-specific df budget, J ≤ q and confounding with the residual when there is one observation per unit and cell
- rank deficiency and empty cells under the sequential aliasing rule
- term-level GVIF and scale disparity
- differences between the raw data and the analysis sample
- labels that differ only in Unicode form
- duplicates against the declared observation key

The T1 audits require the outcome-access argument, and the separation check runs as an exploratory T2 audit (02-decisions.md, Q2 and Q3).

The pathology zoo grows from nine prototyped fixtures, one of them (Z01) with its matched negative, to the thirty fixtures specified in Q8 (02-decisions.md). The generators live in sim/ so that the simulation studies reuse them. Disclosure-attack tests on the privacy filter run in CI. M2b-2 wrote them ahead of the zoo in sim/disclosure/ (its README): a consistency search over families of small tables at a minimum count of 3, an interval audit by linear programs of the relations that one document states, an attack on each channel that the reviews of M2b-2 found and documents that validation must refuse, which run on pull requests that touch the R package, spec/, the privacy cases of the audit corpus or the tests, with mutation testing of the filter and a check of earlier commits run by hand. M2c adds the zoo to their families.

The data layer of M2a (steps 1 to 4) settles these points:

- docs/spec/tables.md (Keys) now states that the primary key is checked record by record, both codes in each record before the next, so that a repeated key is reported before a missing value in a later record and the reverse. The two table readers had read the paragraph in two ways, and no case separated them, so the table corpus gains tables-keys-019 and tables-keys-020 (194 cases).
- docs/spec/ir.md settles five points that it left open: a subtracted random term is refused (E6014), since lme4 adds it, a non-finite value gives E6073 when the builder computes the mean centring constant of its own column, the argument {number} of E6006 for an exponent that is not a number is the text of its first token, the builder of the design matrices reports E6073, E6071, E6072, E6073 and E6071 in a stated order, and a declared event level decides the response vector of every response that has one, since the IR does not record whether a response of integers has declared categories.
- `formula_ir()` returns the IR in the form that the strict reader returns: named lists and unnamed lists in R, dicts and lists in Python, strings marked UTF-8 in R, numbers as doubles in R and as int in Python (term indices, significant digits, integer levels and references) and booleans as logical or bool. The order of members does not affect its canonical bytes.
- `design_matrices(ir, data)` checks the IR's version (E1441) and its schema, refuses a mean centring rule without its constant with an ordinary error and returns a list (R) or dict (Python) with the members `design_sample` and `analysis_sample` (row positions in the data, from 1 in R and from 0 in Python), `x` (a double matrix in R, with the column names, and a two-dimensional numpy float64 array in column-major order in Python), `x_columns` (the names of the columns of X), `x_dropped` (the names that the sequential rule drops, in column order), `z` (a Matrix::dgCMatrix or a scipy.sparse.csc_array, with one stored entry for each row and each column of a random term, zero or not), `z_columns` (a data frame with the columns `term`, the position of the random term in the IR from 1 in R and from 0 in Python, `level`, the label of the level, and `column`, the name of the term's column), `response` and `trials` (double vectors over the analysis sample, or NULL and None) and `offset` and `weights` (double vectors over the design sample, or NULL and None). The rule of E6101 on IR documents waits for the plan validator of M3.
- The data that `formula_ir()` and `design_matrices()` read is a data frame whose columns hold numbers, strings or booleans: in R double, integer, character, factor (its labels, with its level order ignored) and logical columns, and in Python the columns that `read_table()` returns and columns of numbers, strings, booleans or a pandas categorical of strings, read the same way. Only NA (R) and None or pandas.NA (Python) are missing, and NaN and the infinities are values, as `read_table()` returns them. Column names must be valid and distinct after NFC, and a column that the table block declares must hold values of its type unless all its values are missing. Any other data give an ordinary error, and so do offset, weights and trials columns that do not hold numbers in `design_matrices()`. Missing-value strings are not applied to data in memory, so that the IR and the design matrices read the same rows without a declaration. Applying declared missing values to a data frame in memory, as tables.md foresees, is left to the entry point of M2b, which holds the declaration and the data together.
