# Parity

This directory holds the cross-language harness, which compares the outputs of the R and Python packages (02-decisions.md, Q7). It runs both packages over every case of the conformance corpora in [fixtures/conformance/](../fixtures/README.md) and compares each outcome with the outcome of the other language and with the expected outcome that the case states. It compares outputs by the rules of [docs/spec/conventions.md](../docs/spec/conventions.md) (Comparison across languages): error codes, issues with their messages and locations, canonical bytes, hashes and every count, category, name and label exactly, and real statistics and the messages that render them within the tolerance stated there. Every output of M1 and M2a is compared exactly, except the response, trials, offset and weight vectors of the design matrices, which ir.md compares within a tolerance because they can hold logarithms.

| File | Contents |
|---|---|
| `parity.py` | the driver: it writes the plan of a run, runs both packages, compares their outcomes, prints every mismatch and a summary and sets the exit status. It needs only the standard library of Python 3.11 or later. |
| `run_r.R` | runs the cases with the installed R package and writes its outcomes |
| `run_python.py` | runs the cases with the installed Python package and writes its outcomes |
| `differential/` | the differential test of the two packages on the tables of the disclosure-attack harness, on generated designs and on edge cases (Differential test below) |
| `corpora.json` | every JSON corpus file of fixtures/conformance/ with the kind of its cases. A file marked `pending` is counted but not run until the milestone it names implements what it tests. `pending_parts` maps a part of the cases of a file to the milestone that implements it: the runners skip that part, and the harness counts it and runs the other parts. |

## Running the harness

Install both packages, the R package with the suggested packages yaml and lpSolve, without which outcome.separation is not available, and the Python package with its extra 'yaml', then run the harness from the repository root:

```bash
mkdir -p /tmp/parity/rlib
R CMD INSTALL --library=/tmp/parity/rlib r
python3 -m venv /tmp/parity/venv
/tmp/parity/venv/bin/pip install './python[yaml]'
python3 parity/parity.py --python /tmp/parity/venv/bin/python --r-lib /tmp/parity/rlib
```

`--python` names the interpreter that runs the Python package, by default the one that runs parity.py, and `--r-lib` a library that R searches before its own. `--rscript` names another Rscript. R runs once with LC_ALL set to each locale given with `--r-locale`, by default C.UTF-8 and C, so that the cases whose output a locale could change are run in both (fixtures/conformance/unicode/README.md). The harness stops if R does not get the locale it asked for. `--keep DIR` keeps the plan and the outputs of the runs in DIR, and `--compare-only` with `--keep` compares the outputs already there without running the packages again. A run takes about a minute and a half, most of it in the audits that R runs in each locale.

The exit status is 0 when every case gives its expected outcome in every run and the runs agree, 1 when a case does not and 2 when the harness cannot run, for example when a corpus file is missing from corpora.json or a package cannot be loaded.

The workflow [parity.yaml](../.github/workflows/parity.yaml) runs the harness, and in a second job the differential test below, on every push to main and every pull request that touches either package, spec/, fixtures/, this directory or the files of sim/disclosure/R/ from which the differential test builds its inputs, with R release and Python 3.11.

## What is compared

Each case gives one outcome for each of its parts: each mode of a reader or writer case (plain, data and hashable), the hash in memory and of a file for the cases of hash/sha256.json, the parts of table, formula, audit and results cases listed below, and one outcome for every other case. An outcome is the canonical bytes with their hash, and for some reader cases the bits of the double read, or the list of issues reported, or another value such as a decimal string, an NFC form, an order, a digest, a key identifier or a commitment. Any issue raised as a warning is part of the outcome, and an error that is not one of the package's own errors is recorded with its message, so that a crash appears as a mismatch rather than stopping the run.

Table cases have a part for the table read and, with a formula, one for its samples. Formula cases have a part for the IR and, when the case gives the design matrices, one for them and one for the vectors, or, when it gives the issue that the design matrices report, one for the matrices that holds that issue. Audit cases have a part for the run in internal mode and, in privacy.json, one for the run in shareable mode. Results cases have a part for the document validated alone and, when the case gives a sidecar, one for the document validated with its sidecar, data and declaration.

- A table read is the list of columns, each with its name, its type and its values as the table corpus writes them, by the type of each value that the package returns: null for a missing value, strings and booleans as themselves, the integers of an integer column as integers and every other number as the bits of the double, with negative zero as zero, or as 'NaN', 'Infinity' or '-Infinity'. So a value of the wrong type in R or Python is a mismatch, and R's strings that are not ASCII must be marked UTF-8.
- The samples of a table case are the design and analysis samples of the IR of its formula, as row positions counted from 0, which both runners compute with `design_samples()`.
- The IR is its canonical bytes in the hashable profile with its hash. The harness computes the expected bytes from the IR of the case and stops unless they have the IR hash that the case states.
- The design matrices are the rows of the design sample, X with the names of its columns and those that the sequential rule drops, Z with the description of its columns and the number of entries it stores, which is one for each row and each column of a random term. Their values are compared bit for bit.
- The vectors are the response, trials, offset and weight vectors of the design matrices, which the corpus does not give. They are compared across the languages alone, each value within the tolerance of conventions.md, since ir.md compares them within a tolerance.
- An audit part runs `audit()` with the data frame of the case, built as for a formula case, its other inputs, the commitment key 00 01 02 … 1F and MIXEDCHECK_TIME set to 0 (fixtures/conformance/audits/README.md). Its outcome is the issues of the error that refuses the run, compared exactly, or the canonical bytes in the data profile of the document and of the sidecar. The findings of the checks of the case are compared with the expected findings by the rules of that README, and the documents and sidecars of the runs with each other by the rules of conventions.md: every member exactly apart from `created`, `software` and the package version in `versions`, which are not compared, and each finding exactly apart from its real statistics, which match within the tolerance of their check or bit for bit for those that the case lists in `exact`, and its message, which matches by its values. A finding that is near_threshold in either outcome may differ in what conventions.md allows. A mismatch lists the members that differ by their JSON Pointers.
- The outcome of a results part is 'valid' when `validate_results()` returns, with the warning W7090 for a document of another registry, or the issues of its error, compared exactly with the issues and sidecar issues of the case (fixtures/conformance/results/README.md). An error in the document stops validation before the sidecar, so that the second part then repeats the first.

A case with `languages` runs only in the languages it lists, and its outcomes are compared with the expected outcome alone. A run that reports a code which spec/errors.json reserves for the other language is a mismatch (docs/spec/errors.md).

The harness also reads, through each package, every JSON file of spec/ that spec/vendoring.json vendors, in the data profile, and compares the canonical bytes and hashes across the languages. The registry that `read_registry()` returns must give the bytes of spec/compiled/registry.json, and `spec_versions()` the content of spec/versions.json.

## Reports

Every mismatch is printed with the case, the part, the expected outcome and the outcome of each run, runs with the same outcome together. Strings are shown with characters that a terminal may not show escaped, and where canonical bytes differ, the first differing byte is shown in context. A summary follows, with the number of cases in each corpus file, the number run in each run and in both languages and the result. The outputs are JSON Lines: a header that names the run, the package, the interpreter, the version of the YAML package and, for R, the locale, then one record for each part of each case with every string written as the hexadecimal digits of its bytes, so that the two runners write identical records for identical outcomes.

## Adding a corpus

A new JSON corpus file must be listed in corpora.json, or the harness stops. A file of an existing kind needs nothing else. A new kind needs a function in run_r.R and in run_python.py that computes the outcome of each part, and the expected outcomes in `expected_parts()` of parity.py, written from the README of the corpus. A kind whose outcomes match by rules other than equality and the tolerance of real values also needs functions that compare and show them, which `compare_runs()` passes to `Report.compare()`, as `audit_differences()` and `show_audit()` do for the audit corpus.

## Differential test

The directory differential/ holds the differential test of the two packages, which runs both on inputs for which no corpus states an outcome and requires their outcomes to agree. Its inputs are every table of every family of the disclosure-attack harness ([sim/disclosure/R/families.R](../sim/disclosure/R/families.R)), at the family's k, realistic designs generated from seeds, at the k of the registry, edge cases generated from seeds, each at its own k, and the tables of the regression attacks of the harness ([sim/disclosure/R/regressions.R](../sim/disclosure/R/regressions.R)), at the k that each attack sets. Each input runs in internal and in shareable mode in each language. The test compares the privacy filters of the two packages on the tables on which the harness attacks the filter of the R package ([sim/disclosure/README.md](../sim/disclosure/README.md)), and the 24 checks on inputs that the audit corpus does not hold. Since no entry of registry 0.1.0 writes labels, it also runs steps 2, 10 and 11 of the filter, which give the pseudonyms, on cases of findings of a check that writes them.

| File | Contents |
|---|---|
| `differential/differential.py` | the driver: it writes the inputs unless they exist, runs both packages on them in shards, several at a time, compares the outcomes, prints a summary, every kind of difference and the comparisons that differ with what reproduces them, and sets the exit status. It needs only the standard library of Python 3.11 or later and parity.py, whose comparison of audit documents it applies. |
| `differential/inputs.R` | writes the inputs, running the regression attacks on the installed R package to record their tables: index.json, which lists the files of inputs with the identifiers of the inputs of each and the tables that their families cannot build, and the files, each of at most 40 inputs and, past its first input, of at most 4,000 rows |
| `differential/designs.R` | the realistic designs |
| `differential/edges.R` | the edge cases |
| `differential/run_r.R` | runs a shard of the inputs with the installed R package and writes its outcomes |
| `differential/run_python.py` | runs a shard of the inputs with the installed Python package and writes its outcomes |
| `differential/pseudonyms.R` | runs the pseudonym cases with the installed R package and writes their outcomes |
| `differential/pseudonyms.py` | runs the pseudonym cases with the installed Python package and writes their outcomes |

### Inputs

The families give 8,969 tables in 34 families, each built by the family's `build()` from one row of `dh_grid()` and run at the family's k, which is 3 for every family but four-sizes, which runs at 4. `--widen 1` widens every range by one value at each end that is not a natural bound, as the harness does when it looks for a leak beyond a family's ranges, and gives 35,330 tables. The designs are six studies.

- repeated: 24 to 36 subjects measured on up to six occasions, with dropout, time as an integer column, age as a subject covariate, random slopes of time and, for one seed in three, precision weights.
- crossed: 18 to 26 subjects crossed with 12 to 20 items in an incomplete design, a condition that varies between items and within subjects, with random slopes, item labels in Latin script with accents, Greek, Cyrillic and Han and one outside the Basic Multilingual Plane, and, for one seed in three, an item spelt in two Unicode forms and simple contrasts.
- schools: pupils in two to four classes in each of 8 to 12 schools, class labels repeated in every school and declared within_parent, an arm assigned by school and, for one seed in three, a baseline score with missing values as a sample column.
- within-three: a within-subject factor of three levels, with two or three trials of each level by subject, age as an integer covariate, treatment, sum and simple contrasts, centring by the mean and three random parts across the seeds.
- singletons: 50 to 70 subjects of one to nine rows, most of them of one row, a covariate that varies within subjects and a logical predictor that does not, missing for three subjects for one seed in three, and no disclosure unit for odd seeds.
- pairs: pairs of two persons in the roles A and B, some pairs of one person, each person measured twice alone and twice together, with the interaction of role and condition and, for one seed in three, sum contrasts.

Each design has a gaussian outcome, whose family odd seeds leave to its default, a Poisson outcome and a binomial outcome with a trials column of 4 to 12 trials that the declaration names, at T0, T1 and T2, with no row, one row, three rows, k − 1 rows and a third of the rows without an outcome, the same rows for every outcome and tier of a seed. The first seed of every three attests at T1 and T2 that the outcome was seen. The structure of a design depends on its seed alone, so that its variants differ only in the outcome, the tier and the rows without an outcome. Three seeds, the default, give 810 inputs, and `--seeds N` gives 270 × N.

The edges are eight generators of inputs where the two filters, and the checks whose values they read, are most likely to differ. Each seed gives one input, at a k drawn from 2 to 20 and a tier drawn from T0, T1 and T2, or T1 and T2 where the edge needs the outcome, with the attestation that the outcome was seen for one seed in four.

- ties: 4 to 42 subjects whose numbers of rows come from a few values, such as all equal or ones and twos, so that the quantiles of the level sizes tie and lie on either side of the quantile rule, a nested factor for even seeds and a covariate with ties. No row, one row, the rows of up to three subjects or a third of the rows lack an outcome.
- scripts: subjects in a grouping column named 'élève' and a fixed factor of three to five levels, labelled in Latin, Greek, Cyrillic, Han, Arabic, Hebrew and Thai script, with characters whose order differs between code points and the collation of most locales, such as 'Z' and 'a', 'Å' and 'Z' or 'ß' and 'ss', labels that NFC merges, such as 'é' composed and decomposed or the Angstrom sign and 'Å', quotation marks, a label outside the Basic Multilingual Plane and, for one seed in five, the empty string, beside two further grouping columns, 'Zone' and 'ábaco', whose labels, such as 'Åsa', 'Zeta' and 'alpha', sort differently by code point and by locale. The fixed factor is a factor whose levels are in reverse order with an unused level for one seed in four, has a coding with a drawn contrast and reference level for another and declared categories whose first, the reference level, has no row for a third.
- sparse: 5 to 25 subjects of one to six rows, a factor with a level that no row holds and one that few rows hold, up to four subjects without any outcome and, for one seed in seven, no outcome at all, with gaussian, Poisson and bernoulli outcomes.
- trials: binomial outcomes whose trials are 0, 1, 2 or 5 and missing in up to two rows, and bernoulli outcomes of the strings 'yes' and 'no' with a declared event level.
- offsets: Poisson counts with log(e) as an offset, an exposure declared on the raw scale or e as an offset with precision weights, of which one is missing for one seed in eight and 0, which `audit()` refuses with E6072, for another.
- slopes: subjects crossed with items in one to four blocks, so that the design has as many connected components, with correlated and uncorrelated random slopes, a slope without an intercept, classes nested in schools and the interaction of subject and item.
- assignments: an arm assigned by school, a dose assigned by class in blocks of schools, a condition within pupils that was not randomised, an assignment without a level, an arm missing in two rows, two assignments at once and an arm that varies within a school that the declaration assigns as a whole.
- units: no declaration, units of which none is a participant, two participants, a disclosure_unit that names a site and a participant unit labelled by two columns.

`--edge-seeds N` sets the seeds of each edge, 25 by default, which give 200 inputs.

The regressions are the tables on which the regression attacks of the harness run `audit()`, one input for each run of an attack, such as the two tables of a pair attack, each at the k that the attack sets. inputs.R runs every attack on the installed R package with the function of the harness that runs a table replaced by one that records it, so that the inputs follow the attacks as they change, and the 75 attacks give 93 inputs.

Each file of inputs holds a list of inputs, each with its identifier, such as family/sizes/13, design/crossed/binomial/T2/missing-9/seed-3, edge/scripts/seed-7 or regression/R9-items-rows/2, its source, which rebuilds it (the family with the values of its parameters, the design with its outcome, tier, rows without an outcome and seed, the edge with its seed, or the attack with the position of its run), its k, its formula, the other arguments of `audit()` that it sets (declaration, family, coding, weights, sample_columns, outcome_access, reason, exploratory and outcome_seen) and its data, as a list of columns in order. Each column has its name, its type, 'double', 'integer', 'logical', 'string' or 'factor', the levels of a factor in their order and its values, with null for NA and, in a double column, the strings 'NaN', 'Infinity', '-Infinity' and '-0' for the special values. The canonical writer of the R package writes the files in the data profile and the strict reader of each package reads them, so that every double and every string, in UTF-8 and in the Unicode form of the data, reaches both packages unchanged. R builds each column with its type. Python builds a column of float64, or Float64 when it has NA, so that NaN stays a value and NA a missing value as in R, of int64 or Int64, of bool or boolean, a Categorical with the levels of the factor in their order and, for strings, a column of the type that pandas gives a list of strings. Both packages read a factor by its labels and take the levels of a categorical predictor from the declaration or from the table in code-point order (ir.md, Kinds of columns), and the factors of the designs have their levels in another order, which neither package may use.

The pseudonym cases, which differential.py writes to pseudonyms.json in the work directory with a fixed seed, each hold a k from 2 to 20, a commitment key and one to six findings of the check structure.flagged_levels, which writes labels and which the unit tests of both packages define, each with a grouping factor named as the IR names it, such as 'school', 'school:class' or '`élève`', zero to nine labels, its distinct contributors, 1, k − 1, k, k + 1 or 50, and, for about one finding in seven, contributors that dominate. Most labels come from a list with characters that sort differently by locale, Unicode forms that NFC merges, quotation marks, a tab, a control character, a noncharacter, white space, the empty string and the strings '#1' and '#2', and the others are strings of one to six characters drawn from ranges of Latin, combining, Greek, Cyrillic and Han characters, the noncharacters at the end of the Basic Multilingual Plane, mathematical letters and emoji. The same label recurs within a factor and across factors. `--pseudonym-cases N` sets their number, 2,000 by default, and 0 runs none.

### Running the test

With both packages installed as for the harness, from the repository root:

```bash
python3 parity/differential/differential.py --python /tmp/parity/venv/bin/python --r-lib /tmp/parity/rlib
```

The test writes the inputs to a temporary directory with inputs.R, which runs with LC_ALL set to C.UTF-8, and runs R with LC_ALL set to `--r-locale`, by default C.UTF-8. In the C locale R reads the same inputs, since the strict reader marks their strings as UTF-8. `--cores N` runs N shards at a time, by default as many as the machine has cores, and `--shards N` divides the files of inputs into N shards for each language, by default three times `--cores`. `--seeds`, `--edge-seeds`, `--widen`, `--families`, `--designs`, `--edges` and `--regressions`, with names or identifiers of attacks separated by commas or 'none', choose the inputs, `--inputs DIR` reads inputs that inputs.R wrote before and `--generate` writes them again. `--only ID ...` runs the inputs named, without the pseudonym cases. `--keep DIR` keeps the inputs, in DIR/inputs unless `--inputs` names another directory, and the outputs of the runs, and `--compare-only` with `--keep` compares the outputs already there. `--report FILE` writes every count and difference as JSON, and `--shown N` sets how many comparisons that differ are shown in full, 20 by default. The test stops when the two packages read different compiled registries, as when one of them is installed from a tree whose registry has changed, since every document would then differ at /inputs/registry_hash.

The exit status is 0 when the two packages agree on every comparison, 1 when a comparison differs or a run fails and 2 when the test cannot run.

### What is compared

Each run calls `audit()` with the data frame and arguments of the input, the privacy mode, the commitment key 00 01 02 … 1F and MIXEDCHECK_TIME set to 0, after setting min_count to the input's k in the registry that the package has read, as the harness does in R. Its outcome is the canonical bytes in the data profile of the document without `created`, `software` and the package version in `versions`, which conventions.md does not compare across languages, and of the sidecar, or the issues of the error that refuses the run, or the text of any other error, with the issues of any warning. The two outcomes of an input in one mode give one comparison, which is

- identical, when the outcomes are equal: the same canonical bytes of the document and the sidecar with the same warnings, or the same issues
- within tolerance, when the bytes differ but the rules of conventions.md (Comparison across languages), as parity.py applies them to the documents of the audit corpus, find no difference: real statistics within their tolerances, messages by their values and the latitude of a near_threshold finding
- different, otherwise, with each difference as the JSON Pointer of a member and its value in R and in Python.

A run that fails with an error that is not one of the package's own is reported as a failure, whatever the other language gave.

Each pseudonym case is run once in each language, with R in the locale of `--r-locale`: step 2 of the filter applies to each finding, then steps 10 and 11 give the pseudonyms, number them by the HMAC-SHA-256 of the factor and the label under the case's key, replace the labels and render each message, from its template when the labels are written and from its fallback when step 2 suppresses them. Its outcome is the canonical bytes in the data profile of the written findings and of the pseudonyms in the form of the internal sidecar, and the two outcomes of a case give one comparison, identical or different.

### Reports

The summary has a line for each family, design or edge and mode, and one for the pseudonym cases, with the number of comparisons of each class, and the totals, which count the pseudonym cases with the shareable comparisons. The runs that failed follow, then each kind of difference, a JSON Pointer with the index of its finding replaced by the check of the finding, with the number of inputs that give it and the first three of them. Each comparison that differs is then shown with the input that reproduces it, what rebuilds it and the file that holds it, the command that runs that input alone and its differences, each with the value of R before that of Python. The report ends with the slowest inputs in each language and the time of each stage. The outputs of the runs are JSON Lines compressed with gzip, one file for each shard and language: a header that names the run, the package, the registry hash, the interpreter and, for R, the locale, then one record for each input and mode with the time of the run and its outcome, every string written as the hexadecimal digits of its bytes. The outcomes of the pseudonym cases are r-pseudonyms.txt and python-pseudonyms.txt, one line of hexadecimal digits for each case.

### Time and continuous integration

On a machine with four cores, with R 4.3.3 and Python 3.13, the default run of 10,072 inputs, the 200 edge cases and the 93 tables of the regression attacks among them, and 2,000 pseudonym cases took about 9 minutes: 34 seconds to write the inputs, which includes running the regression attacks in R, 1,524 seconds of R and 360 seconds of Python summed over the shards, which ran four at a time, and 32 seconds to compare. The pseudonym cases took 13 seconds in R and 1 in Python. The shards would take about 15 minutes on two cores.

The default run fits within 30 minutes on two cores, so continuous integration runs every input of it. The job differential of [parity.yaml](../.github/workflows/parity.yaml), on the events and paths of the harness, sim/disclosure/R/families.R, harness.R and regressions.R among them, installs the R package with lpSolve and the Python package under Python 3.11, as the harness job does, and runs

```bash
python3 parity/differential/differential.py --python "$RUNNER_TEMP/venv/bin/python" --r-lib "$RUNNER_TEMP/rlib" --cores "$(nproc)"
```

with a timeout of 45 minutes. The widened grids and more seeds of the designs and edges, `--widen 1 --seeds 12 --edge-seeds 250`, which took about 37 minutes on four cores in four runs of parts of the inputs that `--families`, `--designs` and `--edges` choose, three of about 11 minutes of the families and designs and one of 3 minutes of the edges and the pseudonym cases, are run by hand before a release and after a change to the filter, with R under C.UTF-8 and C and with Python 3.11 at the floors of its dependencies as well as Python 3.13.

### Result of the differential test

In M2b-3, before the port of the privacy filter, on R 4.3.3 and on Python 3.13 with pandas 3.1 under Linux, the test ran the 9,779 inputs of the default run. In internal mode the two packages agreed on every input: 1,083 comparisons were identical and 8,696 within tolerance. The differences within tolerance are real statistics that conventions.md compares within a tolerance, condition_number, smallest_eigenvalue, gvif and gvif_per_df, the bounds and the optimum of outcome.separation, icc and within_share, and the threshold_proximity of five findings of outcome.separation in the family two-factor-separation, tables 61, 111, 121, 181 and 231, which are near_threshold in Python and clear in R. The five findings bound a coefficient whose exact bound over the optimal face is 1e-6, the separation tolerance, which is also the lower end of the proximity band of involvement_tolerance, 1e-5 divided by its proximity factor of 10 (registry.md, Parameters). R computes the bound as 9.999999994736442e-07, below the band, and Python as 1.0000000002508003e-06, in it, both within bound_tolerance of the exact value, so the difference is one that conventions.md allows and neither package is wrong. The 35,317 tables of `--widen 1` that the families can build, the designs with 12 seeds, 3,240 inputs, the inputs whose labels lie outside ASCII with R in the C locale and four families with Python 3.11 and the floors of its dependencies, pandas 2.3.0 and numpy 2.3.0, gave the same result: no comparison in internal mode differed, and the only member that differed beyond the last digits of a real statistic was the threshold_proximity of the same five findings. The family blocks cannot build 13 tables of its widened grid, which the harness leaves out too.

After the port of the privacy filter to Python, on the same versions, the default run gave the same comparisons in internal mode and, in shareable mode, 5,556 identical comparisons and 4,223 within tolerance, none different, and so did the inputs whose labels lie outside ASCII with R in the C locale, 111 and 108. The five findings of two-factor-separation that differ in threshold_proximity in internal mode are suppressed as a whole in shareable mode in both languages, by the rules of privacy.md (Decisions) on outcome.separation.

A review of the port then ran every input in both modes: the 35,317 widened tables, the 3,240 inputs of the designs with 12 seeds and the 2,000 edge cases of `--edge-seeds 250`, 40,557 inputs that hold every input of the default run, with 2,000 pseudonym cases. The outcomes of R were the same, byte for byte, under C.UTF-8 and C, and under en_US.UTF-8, whose collation orders letters otherwise than code points do, on the default inputs and the edge cases. ### Time of a shareable audit

On the same machine, `audit()` ran in a T1 run of a gaussian model, `y ~ x + cond + (1 | school) + (1 | subject) + (1 | item)`, on tables of 1,000 to 300,000 rows with subjects of ten rows each, nested in 20 schools, 40 items crossed with the subjects and one outcome in fifty missing. The times are the least of five runs, or of three from 100,000 rows, in seconds, and those of the filter come from runs that time its functions.

| Rows | R, internal | R, shareable | R, filter | Python, internal | Python, shareable | Python, filter |
|---|---|---|---|---|---|---|
| 1,000 | 0.12 | 0.16 | 0.05 | 0.05 | 0.06 | 0.01 |
| 10,000 | 0.35 | 0.51 | 0.18 | 0.16 | 0.18 | 0.05 |
| 100,000 | 3.03 | 4.38 | 1.67 | 1.65 | 1.92 | 0.40 |
| 300,000 | 9.06 | 13.30 | 5.05 | 5.39 | 6.81 | 1.35 |

The filter of each package grows about as the rows, from 10,000 to 100,000 rows by a factor of about 9 in R and 8 in Python and from 100,000 to 300,000 by 3.0 and 3.4, as the times in the table give them. Most of its time goes to step 7, which codes the items and resolves the class of their counts in every sample. Two steps of the Python filter grow faster than their R counterparts: resolve_count_class(), which the checks call too, by a factor of 14.9 from 10,000 to 100,000 rows where R's grows by 10.0, and privacy_items() and privacy_item_quantities() by 3.8 from 100,000 to 300,000 rows where R's grow by 3.1 and 2.8. Both code levels with pandas.factorize(), a hash table whose time per value rises once it outgrows the processor's caches, as that of R's match() does at these sizes, and no step does more than n log n operations in the rows. At every size the Python filter took about a quarter of the time of the R filter.
