# Disclosure-attack tests

These tests attack the privacy filter of shareable mode ([privacy.md](../../docs/spec/privacy.md)) as an adversary would, on documents that the R package writes, and fail when a document gives back a value that privacy.md undertakes to hide. They run in CI on every pull request that touches the R package, which holds the filter, the writer of findings, the IR hash and the validator, the specification, the privacy cases of the audit corpus that the regression attacks read, the pathology zoo, whose stored instances and generators the tests read, or these tests (`.github/workflows/disclosure.yaml`), and never inside `R CMD check`. Nothing here ships with either package.

## Threat model

The adversary of privacy.md holds one shareable results document. They know the package, the registry and the specifications, so they know every definition, rule and detail of suppression, and they can test candidate values against an unkeyed hash, such as the IR hash. They know the values that a predictor can take, its recording grid or the set of its values, but not which rows hold them. They cannot invert a keyed commitment. They do not hold the data or a second document of the same data, against which privacy.md (Guarantees) makes no promise. They can know the declaration: the document names the disclosure unit in `/privacy/disclosure_unit` and writes the hash of the declaration unkeyed in `/inputs/declaration`, against which a guessed declaration can be tested, and privacy.md (Guarantees) takes the possible values of a hidden value over the tables and declarations whose documents read alike, so that in effect the declaration is fixed.

privacy.md protects two tiers of values (Tiers), as the maintainer decided on 11 November 2026 ([02-decisions.md](../../docs/design/02-decisions.md), Q5). A value is outcome-derived, tier A, when it would change if only the outcome column or its trials column changed, their values or which rows lack them: every statistic, support count, status and message of a finding of a T1 or T2 check, the quantities of the analysis sample and the difference between a quantity of the analysis sample and the same quantity of another sample. A value is a design-structure value, tier B, when it depends only on the predictors, keys, labels, grouping columns, assignments and the declaration: every value of a finding of a T0 check and the quantities of the table, the design sample and the rows of assignments and pairs.

The guarantees read a document through its strict reduction (`dh_reduce(strict = TRUE)`), without the time of creation, the digests of keyed commitments and the values that privacy.md accepts to show: the statuses, messages, categories, booleans and names of the T0 checks, the availability of a finding that is not available, the verdict of outcome.separation and its suppression as a whole, the class of a by_unit count (`dh_strict_finding()` writes a non-person by_unit count below k as if suppressed below k, which would otherwise show the class), the boolean `dominated` and a quantile implied by a written count or shared by k or more of its values. A hidden value is one that the document does not write and that no written count measures, and the tables whose documents have the same strict reduction leave it a set of possible values. In these terms:

- A hidden outcome-derived value has two possible values or more, unless every table of the design structure gives it one, as a difference of 0 does when the larger sample's quantity is 0, or the value of a count that the document writes, as the analysed levels of a disclosure unit whose members each have one row take the value of the analysed rows. A hidden outcome-derived count whose detail is not 'min_count', 'min_count_rule' or 'dominance' has a possible value of k or more, unless the bounds that details state keep it below k or rule 1 of Across findings hides it as a difference below k, which its firing displays as 'min_count' would. The adversary may use any inference, through design-structure values too.
- A hidden design-structure count keeps two possible values or more under the linear relations of the document: sums, differences and parts of totals that definitions state, the quantities that several counts measure, with the offsets by which the counts of columns measure levels where the formula fixes them, the same quantity in nested samples, the numerator and denominator of a ratio, the bounds that details state and every count at least 0. Every other inference about design-structure values is residual risk (privacy.md, Guarantees, Residual risk), which these tests report without failing.

The harness classifies every target by this definition in one function, `dh_tier()` (`R/harness.R`): a statistic, support count or status by the tier of its check, T1 and T2 tier A and T0 tier B, a quantity of the analysis sample and a difference from it tier A, a quantity of another sample tier B, and a parameter of a family by the tier that the family states. A hidden value without a tier is an error of the harness, and so is a parameter whose stated tier the tables of its family contradict: one of tier B that differs between two tables that differ only in the outcome column and its trials column, or one of tier A that never does although it takes two values (`dh_parameter_tier_issues()`). Every run of attacks (a) and (b) applies both tests to every table of every family.

## The attacks

(a) Inference by consistency search (`R/consistency.R`, `R/families.R`). A family is a template of small tables whose free parameters are counts: cell sizes, events and missing values. The search audits every table of the family in shareable mode, reduces each document to what the adversary can use (`dh_reduce()`: the time of creation and the digests of keyed commitments are dropped, unkeyed hashes kept) and groups the tables whose reduced documents are identical. For each value that the internal findings hold and the shareable document hides, and for each parameter that counts persons and is below k, it reports a determination when the value is the same across a group while the family lets it vary among the tables that hide it with the same detail. A determination that only the full reduction makes is accepted, as are a quantile shared by k or more of its values and a count derived through suppress_with from written statistics. A determination of the strict reduction is a leak when its target is of tier A and residual risk when it is of tier B, since the search cannot tell a linear determination from another.

The 34 families of `R/families.R` hold one grouping factor with levels of one to four rows, crossed and nested factors, a grouping factor that is also a fixed term, a fixed interaction whose combinations are a grouping factor, classes declared within_parent, schools of pupils that count non-persons, a disclosure unit and none, assignments with and without blocks, a predictor of two values and binary factors, bernoulli, binomial, Poisson, gaussian and bounded outcomes, missing outcomes, binomial trials of 0 and missing trials, predictors, keys and assigned columns, k or more levels that lose every outcome beside levels that lose one, up to k + 1 missing values where one sample must exceed another by k or more in one quantity and by fewer in another, a level of one row that loses its only row, duplicated keys, labels with two Unicode spellings, T0, T1 and T2 runs and exploratory mode. The runs use k = 3, which makes tables of 6 to 40 rows meaningful, and four-sizes k = 4: the rules of privacy.md take k as a parameter, so the harness sets min_count in the cached registry, which the filter, the document's `/privacy` and the validator all read, and the package needs no argument for it. The guarantees are checked at the registry's k of 10 by attacks (c) and (v) and at these small k by (a) and (b), where a hidden count below k can be left one value that a larger k leaves several, as The zoo below records. Whether privacy.md states the k from which its guarantees hold, or gains a rule for small k, is an open item of 03-execution-plan.md (M2). The registry's k of 10 is used by attacks (c) and (v).

The families that the two tiers added probe the values that they restore and the rules that protect outcome-derived values through design-structure values:

- chain: subjects of one, two and three rows, subjects of one row without the covariate, rows without a subject under an observation key and second rows without an outcome, in a Poisson T1 run, so that the table, the design sample and the analysis sample differ by counts on either side of k and the comparisons of rules 1 and 4 fire or not beside a design sample that loses its rows to the analysis sample.
- reals: subjects of one, two and three rows with a contrast of -0.5 and 0.5 within them and no, one, k − 1 or k second rows without an outcome, in a gaussian T1 run, which writes no value of the analysis sample, a Poisson T1 run, whose outcome.zero_shares writes it, and a bernoulli T2 run. Its reals are unmasked, so effective_size, icc, smallest_eigenvalue, within_share and the standard deviation would give back the rows of the design sample wherever rule 5 let them through.
- constant-written: subjects of one and two rows, k or more of them with a constant outcome and others without their second outcome, so that outcome.constant_clusters writes the analysis sample's levels with two rows beside the design sample's counts and reals, in a gaussian T1 run.
- non-person: schools of two and three pupils, the disclosure unit, so that the schools count non-persons, schools of one pupil, which make them count persons, and pupils without an outcome, in a Poisson T1 run, where the written levels of a non-person item would bound the rows that the design sample loses.
- cross-tier: subjects of one and two rows that lose their only or their second outcome beside an outcome constant within three subjects, in a Poisson T1 run. Its outcome values follow the rows, so its determinations of attack (a) rest on the template and are candidates, and attack (b) gates it.
- whole-lost: subjects of one, two and three rows, k or more subjects of two rows that lose every outcome beside others that lose their second, in a Poisson T1 run, so that the design sample keeps its levels beside the analysis sample and the sizes of its levels, beside the analysed rows, would give back the second rows that the analysed subjects lost.
- fixed-factor: a grouping factor that is also a fixed term, with levels of two and three rows, levels whose counts are all 0 and levels that lose every outcome or one, in a Poisson T1 run, so that the columns of the term write the design sample's levels and outcome.zero_shares a part of the analysed levels.
- interaction: a fixed interaction of two factors whose combinations are a grouping factor, cells of two and three rows, an empty cell and cells that lose every outcome or one, in a Poisson T1 run, so that the df of the two factors and empty_cells write the design sample's combinations. Its outcome values follow the rows, so its determinations of attack (a) are candidates.
- trials: a binomial outcome whose trials are 0 or missing in some rows, which leave the analysis sample as rows without an outcome do, in a T1 run, with the trials column part of the outcome in `dh_design_key()`. Its determinations of attack (a) are candidates.

In the family eigen the subjects without an outcome reach every subject but one, and in the family bounds the rows between the bounds reach 12, since the design sample now writes the counts from which their former limits made the outcome parameters follow. Every family whose probe reaches a value that the two tiers restore, such as effective_size beside the level sizes or combinations beside the levels of crossed columns, varies independently the counts on which that value depends.

The families blocks, crossed, crossed-unit, labels, nested, keys and fixed-factor have gate TRUE but no table strictly inside the limits of their ranges, since each holds a parameter of two values whose both ends are limits, so attack (a) reports no determination in them unless a run widens them (`--widen`), and their gate applies to attack (a) only then. Attack (a) therefore gates no family that probes design.collinearity, outcome.minority_events, outcome.separation, outcome.zero_shares or structure.id_scope_evidence, and for these checks the gate rests on attack (b), which gates every family, and on the regression attacks. The family zoo-ceiling of the pathology zoo (The zoo, below) gates attack (a) on outcome.boundary_shares and outcome.constant_clusters in a bounded score of two waves, and zoo-latin on the identifiability and structure checks of a Latin square with random slopes and three grouping factors. No family whose attack (a) gates the run holds weights, offsets or exposure, interactions, an emptied reference level, dominance, declared estimands or inferred provenance, nor the 4k levels from which a quartile of the level sizes is written, which a family at k = 2 would reach. Attack (b), which gates every family, reads the documents of the zoo families, which hold random slopes, three grouping factors, a gaussian fixed interaction with an empty cell, an emptied reference level, a declared estimand and pupils declared nested_mobile.

A determination within a family is meaningful only when the family lets the value vary for reasons that the document does not show. Four things ensure this:

- Each family varies independently the counts on which the values that it probes depend (`probe`), including levels of one, two and three rows, rows outside the design sample and outcomes missing in part of a level and in whole levels, since a family in which every level has two rows tells the adversary what no document shows. A family probes only the checks whose counts it varies, and places its zeros, events and missing outcomes so that the written T1 statistics do not follow the parameters that it gates. Reals that depend on predictor values are masked unless every predictor of the family takes two values whose counts are parameters, since the adversary does not know which rows hold the values of a covariate.
- Only tables strictly inside every range that is a limit of the family, rather than a natural bound such as 0, are reported.
- A family whose determinations have not all been traced to a leak or to its fixed structure, such as every subject having two rows, has gate FALSE: its determinations of outcome-derived values in attack (a) are reported as candidates and do not fail the run. The gate applies to attack (a) only, and a leak of attack (b), which reads one document and no family, fails the run in every family.
- When the search finds a leak, it runs the family again widened by one value beyond every such limit (`dh_search()`, `--widen`). The widened tables can join a group and remove a determination that only the limits of the family made. A determination that survives is reported with its reproducer.

The search cannot find a leak in a structure that no family holds, and a narrow family can still report a determination that a richer one would remove: each reported leak should be confirmed by the interval audit or by hand.

(b) Interval audit (`R/intervals.R`). From one shareable document alone, the adversary collects the relations that the specification fixes between its counts: parts of a total, sums and differences that definitions state, the quantities that several counts measure in one sample, the nesting of the table, the design sample, the analysis sample and the rows of assignments and pairs, the levels with one and with two or more rows, the contributors of the basis grouping_factors as the fewest levels, the contributors of the basis rows as the rows, the numerators and denominators of written ratios and the bounds that a detail implies: 'min_count' a value below k, and 'secondary' on `support.contributors.distinct` a value of k or more, as validation reads it. 'secondary' on any other count shows nothing about the side of k, since the rules after step 3 give it in place of 'min_count'. Relations that are not linear are marked `structural` (`iv_add()`): rows against levels and levels with two rows, the positions and order of quantiles, a quantile of 1 against the singletons, combinations against their parts, duplicate rows against duplicated keys, informative rows against informative levels, the finer factor's levels against the coarser and informative levels, spellings against labels, zeros against the levels of zeros and rows against contributors. In the full model it adds the conditions of the decision rule that a status shows, for the conditions of the form 'X is above 0.' and 'X is 0.', and the labels in several combinations, which bound a part to 0 only where the relation shows nesting. For the table and the design sample, it adds the difference of each quantity from the analysis sample's as a target of tier A, apart from the levels with one row, which rule 1 does not compare (`iv_difference_targets()`). A difference of the levels of an item whose counts resolve as non-person, which counts levels of two members or more, is accepted when a written count measures the levels of the larger sample, since privacy.md then writes it as other non-person counts, and is a determination otherwise. The rows, contributors and, for each item, levels, levels with two rows or more and levels with one row of the analysis sample that no written count measures are targets of tier A too (`iv_quantity_targets()`). It adds the bounds that a rule implies when it does not fire, as structural relations: a written part of a hidden person total shows that the total exceeds it, and the sum of the written parts, by k or more (`iv_part_bounds()`), and in `iv_firing_bounds()` a quantity of the table or the design sample that a written count measures beside a shown analysis sample exceeds the analysis sample's by k or more (rule 1), for the rows, the contributors and the levels and levels with two rows of an item whose counts resolve as person counts, written analysed levels of a grouping factor whose column is a categorical variable of a term, or whose columns are the categorical variables of a term, are exceeded by k or more by those of the design sample and the table (the end of rule 1), a written count of the levels with one row of a person item, or of those with two rows, shows the other part to be k or more (rule 2), a written real of a finding on the table or the design sample beside a shown analysis sample shows that its rows, and the levels of a person item that the real reads, exceed the analysis sample's by k or more (rule 5), and a written count of columns over the design sample shows that no person item of its terms whose levels a count measures there has fewer than k (rule 6). Each level of an item whose counts resolve as non-person holds two members or more, which bounds the rows by twice the levels and, with the basis disclosure_unit, the contributors too where no member lies in two levels, as privacy.md (Across findings, rule 1) assumes of every such item. With the basis disclosure_unit, the contributors of a sample are its levels of the disclosure unit that the document names, where a grouping factor has the unit's columns, and when the observation key consists of those columns and keys.duplicates writes the message unique, the rows of every sample equal those levels and contributors, a relation that reads a T0 message, which privacy.md accepts, so that only the full program holds it (`iv_unit_relations()`). The analysis sample counts as shown when a finding of a T1 or T2 check is available, or when none is and a real has the detail 'secondary' while every statistic that its suppress_with names is written, which only rule 5 gives and only beside a shown analysis sample (`iv_shown()`). The analysis sample is then the rows of one of the assignments or pairs on which an available finding lies, whose quantities are its own, through binary variables when there are several (`iv_analysis_rows()`). A document whose T0 findings on rows that are the analysis sample show it, as privacy.md (Across findings) lets them, but in which no real shows rule 5, leaves the adversary unable to tell whether it is shown, and a document that is not shown bounds nothing, so the audit applies no bound of rules 1 and 5 to it, which is all that the document lets the adversary use: in the family assign, 186 of the 546 tables of the widened grid are such documents. The counts of columns enter through the terms of the formula, with the kind and coding of their variables (`iv_shape()`, from the IR, which the formula and the values a predictor can take give the adversary), for the categorical variables that are the columns of a grouping factor (`iv_column_relations()`). df of design.collinearity of a main effect of one categorical variable of L levels in the design sample is L - 1 when no earlier main effect has a kept column, and otherwise lies between L - 1 less the df of the earlier main effects and L - 1. kept of design.rank_deficiency is at least the sum of the df of the main effects, plus 1 when the fixed part spans a column of ones, and equals it when every fixed term is a main effect. columns of design.rank_deficiency, dimension of identifiability.levels_vs_dimension and columns of identifiability.residual_confounding are the columns of their terms in the levels that the IR gives their variables, at least those of the table. budget of identifiability.df_budget and design_df of assignment.design_df lie between their levels or units less kept and less 1. The equalities, whose offset the formula fixes, are linear, and the bounds of an offset that the data set are structural. Linear programs solved with lpSolve, with binary variables where a relation chooses between alternatives, then give the smallest and largest value of every hidden count, rounded inwards to integers, which keeps every integer solution, in two programs: the strict program, without the relations that read accepted values, and the linear program, which also leaves out the structural relations.

- A target of tier A with one value in the strict program is a leak, unless it is a difference of 0 that the design forces because the larger sample's quantity is 0, a difference of non-person levels written beside each other, a quantity of the analysis sample of k or more that the written values alone give or of 0 that the design forces, or an accepted channel explains it. A target of tier A that the strict program shows below k is a leak when the program without the bounds of details still shows it below k (`iv_bound_without_details()`), since a bound that only details give shows no more than the report's '<' k of the counts that carry them.
- A target of tier B is a leak when the linear program gives it one value, and residual risk when only the structural relations do.
- An interval that excludes the internal value is an error of the harness.

(v) Validation attacks (`R/validator.R`). Shareable documents changed to give back a hidden value, as an implementation that broke a rule would write them, which stages 4 and 5 of `validate_results()` must refuse with E7020, E7021, E7022, E7024, E7025, E7045 or E7046. E7023 cannot be attacked with registry 0.1.0, which has no statistic of kind labels, so that a forged label fails E7042 first. Every shareable document of the families must also pass stages 4 and 5.

(d) Mutation testing (`mutate.R`, `R/mutants.R`). Each mutant disables one rule of the filter, of the shareable IR hash or of the validator by replacing a function of the loaded namespace in the harness, never in the package, and the attacks run again. An attack detects a mutant when it reports a leak that it does not report without it, and attack (b) also when a document of a family breaks a relation of its model that no document breaks without the mutant: the bounds that a rule implies when it does not fire hold of every document of the filter, so that a mutant that disables the rule can make the model exclude a value of the document, which then hides from (b) the leak that the mutant opens. Each mutant states the tier of the values that its rule protects, and `mutate.R` exits with status 1 when no attack detects a mutant of a rule that protects outcome-derived values.

(e) Historical check (`historical.sh`). The attacks run against the package as it was at an earlier commit, read with `git archive` into a scratch directory, to measure which leaks of the reviews the harness finds.

## The zoo

M2c adds the pathology zoo ([fixtures/zoo/](../../fixtures/zoo/README.md)) to the tests in `R/zoo.R`, which sources the generators of [sim/zoo/R/](../zoo/README.md) into an environment of its own.

Stored instances. The interval audit reads the documents of designs that no family of `R/families.R` holds, and four of its relations changed with them, each traced through an infeasible subset of the constraints of its linear program:

- The bound of the contributors by twice the levels of an item whose counts resolve as non-person holds only where no member of the disclosure unit lies in two levels of the item, as this README already stated, and the audit now adds it only there (`dh_members_within()`). ## The report

`run.R` prints one line for each leak with a reproducer, the family and its parameters or the attack, then the errors of the harness and the candidates of the families of gate FALSE, and exits with status 1 when there is a leak or an error. A section headed 'Residual risk' follows, with one line for each attack, place and target that determines a design-structure value by an inference other than the linear relations, the number of tables and a reproducer. These lines never fail the run, and they show what privacy.md (Guarantees, Residual risk) leaves open, such as quantiles pinned by the rows and levels, counts of levels with two rows and their parts that the rows and levels give and what the four regression attacks of tier B recover. `dh_known_channels()` would list a channel of outcome-derived values, or a linear relation of design-structure values, that privacy.md records as open, whose leaks the report lists apart. It lists none. The linear relation between the columns of a categorical variable of a term and the levels of an item into which the variable divides the rows, which it listed until 12 November 2026, is closed by rule 6 of Across findings and gated by R8-column-levels, and the two channels that it listed before the two tiers, a quantile below k that the rows, the levels and the singletons pin, and the levels with one row that the sizes of crossed factors bound, are residual risk.

## The Python package

M2b-3 carries these attacks over to the filter of the Python package by parity rather than by porting the harness, since attack (a) reads the internal findings through the R namespace to know which values a document hides, and every attack sets k in the cached registry of the R package. The differential test of the parity harness ([parity/differential/](../../parity/README.md), Differential test) writes every table of the families, with its formula, its arguments and its k, 9,573 tables at each family's k, 604 of them in the families of the zoo, and, with `--widen 1`, the 37,320 of the 37,333 tables of the widened grids that the families can build, and every table on which a regression attack of (c) runs `audit()`, 104 tables of the 83 attacks at the k that each sets, beside 810 generated designs, 200 edge cases and the 60 directories of the zoo at k = 10 and k = 3, 10,807 inputs by default, and 2,000 cases of findings that write labels. It runs `audit()` on each in both languages and both modes, with min_count set to the table's k in the cached registry of each package, as the harness sets it in R, and requires the shareable documents and sidecars to agree by the rules of conventions.md (Comparison across languages). A Python document that agrees with the R document gives back no more than the R document, so the determinations that attacks (a), (b) and (c) make on the R documents cover it, and a leak of the Python filter shows as a difference. The job differential of [parity.yaml](../../.github/workflows/parity.yaml) runs the default inputs, in two parts, on every pull request that touches either package, the specification, the generators of the zoo or R/families.R, R/harness.R, R/regressions.R and R/zoo.R, from which the inputs are built. A review of the port ran 40,557 inputs and 2,000 pseudonym cases in both modes, with R under C.UTF-8 and C against Python 3.13 and 3.11 at the floors of its dependencies, with no difference, and the default run with the tables of the regression attacks gave none either after the fixes of that review, nor with the zoo in M2c, nor after the review of the zoo, whose widened run was repeated too (parity/README.md, Result of the differential test). The documents of attack (v) are not run in Python. The validators of the two packages agree instead on the cases of the results corpus, which break each invariant that attack (v) breaks, E7020, E7021, E7022, E7024, E7025, E7045 and E7046.
