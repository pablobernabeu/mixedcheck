# YAML corpus

These cases test the YAML authoring of declarations in both packages ([conventions.md](../../../docs/spec/conventions.md) and [declarations.md](../../../docs/spec/declarations.md), YAML authoring): the check of the bytes, the pre-scan, parsing with libyaml, the check of keys, the conversion to JSON with every scalar read as a string and coerced to the type that the schema requires at its position, the hashable profile and the validation of the converted declaration. A valid case gives the canonical bytes of the JSON form and its declaration hash, and an invalid case the issues reported.

| File | Cases | Covers |
|---|---|---|
| valid.json | 13 | the Example of declarations.md in block and in flow style, the scalars of the draft's evidence on YAML typing, scalars that R's yaml package types unless given a handler, categories and event levels typed by their field, booleans and numbers, comments, document markers, block and quoted scalars, CRLF line endings, tabs that libyaml accepts, a folded plain scalar, a JSON text in a '.yaml' file and a '.YML' file name |
| reading.json | 31 | the bytes (a byte-order mark, bytes that are not UTF-8 and U+0000), the pre-scan (directives, tags, anchors, aliases, merge keys, plain scalars that start with '<<', indicators inside braces, the line breaks U+0085, U+2028 and U+2029 and the number of documents), syntax errors, duplicate keys, complex and empty keys and a YAML text in a file read as JSON |
| conversion.json | 24 | scalars that cannot be coerced to a boolean, a number or the integer type of a field, numbers outside the hashable profile, NFD, keys outside the BMP, an unassigned code point and nesting deeper than 64, up to the 1,000 nested collections that libyaml 0.2.6 reads |
| validation.json | 7 | converted declarations that fail stages 2 to 5, among them scalars that stay strings where the schema requires another type |
| precedence.json | 9 | texts that break several rules: the order of the steps of reading, of parser failures and duplicate keys, of the pre-scan and of conversion, which reports the first issue in the order of the canonical serialisation, keys before values |

## Format

The files have the format of [declarations/README.md](../declarations/README.md): a `description` and a list of `cases`, each with an `id`, a `description`, the `path` of its input file relative to this directory and `expected` with `canonical` and `sha256` or with `issues`. The input files are read by the rules of declarations.md, so a file whose name ends in '.yaml' or '.yml', compared in ASCII lower case, goes through the YAML reader and any other through the strict JSON reader. The YAML reader reports one issue, located by byte offset, by JSON Pointer into the converted value or not at all, and the validation of the converted declaration reports its list of issues, as for JSON. A test compares the canonical bytes and the hash, or the list of issues, exactly. The hash of a YAML declaration is the hash of its JSON form, so cases whose descriptions name another case have the same `sha256`.

Some inputs hold CRLF line endings, a byte-order mark, U+0000, tabs, bytes that are not UTF-8 or strings that are not in NFC on purpose, and .gitattributes keeps their bytes as stored.

## Provenance

The cases were written for this project from conventions.md, declarations.md and [errors.md](../../../docs/spec/errors.md) and are MIT-licensed. The scalars of valid/scalars.yaml are those of docs/design/evidence/decisions/E/schema/yaml/scalars.yaml, earlier MIT-licensed work of this project, whose typing by PyYAML's safe_load() and R's yaml.load() the evidence in E/out/yaml_compare.txt records. Here each stays the string it spells.

The expected outputs were derived from the specification with a scratch derivation that is part of neither package: the reader of spec/tools/compile_registry.py for the bytes, the pre-scan, libyaml's events through PyYAML 6.0.3's CBaseLoader and the keys, a conversion written from the position table of declarations.md (YAML authoring) and the validation of the declaration corpus. Each case states its expected codes by hand, and the derivation was required to agree. The rfc8785 Python package 0.1.4 gives every canonical form and hash, and the Example of declarations.md has the declaration hash published there. R 4.3.3's yaml 2.3.8, called with the handlers of conventions.md, reads every text that the derivation parses into the same strings, mappings and sequences. It refuses every text for which the derivation reports E3002 or E3007. That comparison showed that yaml 2.3.8 also types exponents such as '1.0e+3' (float#exp) and the scalars '.na', '.na.integer', '.na.real' and '.na.character', so conventions.md now lists the handlers for these and valid/r_types.yaml tests them. A review that compared the two packages on generated texts then found that yaml 2.3.8 reads a plain '<<', and '<<' followed by a character outside ASCII, as a merge key whether or not it is a key, and that libyaml ends lines at U+0085, U+2028 and U+2029 and reads '?' and ':' inside braces as indicators whatever follows them. The pre-scan now refuses every plain scalar that starts with '<<' and follows libyaml on the other two points, and the cases from yaml-reading-019 on test it. Both packages and the scratch derivation give the expected outcome of every one of them. jsonschema 4.26.0 confirms the structural validity of every converted declaration as for the declaration corpus. [spec/tools/test_declaration_corpus.py](../../../spec/tools/test_declaration_corpus.py) checks the format of the corpus, the hashes, the schema, the scalars of each converted declaration against the YAML text and every issue against spec/errors.json.
