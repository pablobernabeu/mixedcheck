# Changelog

Notable changes to the Python package mixedcheck are recorded here, in the format of [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## Unreleased

### Added

- The package skeleton, with `spec_versions()`, which returns the versions of the registry, the schemas and the canonicaliser in the shared specification vendored into the package.
- The package ships the shared specification: the compiled registry of checks, the error catalogue, the schema bundle and the list of code points that Unicode 14.0 assigns. `spec_versions()` reports registry, schema bundle and canonicaliser version 0.1.0.
- `read_json_strict()` reads JSON in the hashable or data profile or in the plain mode and raises `MixedcheckError`, a subclass of ValueError that carries the issues, with a code of the shared error catalogue for the first problem. `canonical_bytes()` writes a value by RFC 8785 with ECMAScript number formatting, and `canonical_hash()` hashes those bytes. `hash_bytes()` and `hash_file()` return SHA-256 hashes, and `new_commitment_key()`, `commitment_key_id()` and `keyed_commitment()` create HMAC-SHA-256 keyed commitments. The functions have the names and arguments of the R package's.
- `validate_declaration()` checks a declaration of vocabulary 0.1, read from a JSON or YAML file or given in memory, in the five stages of the specification and reports every problem of the first stage that finds any. YAML is read with every scalar as a string and needs the extra 'yaml' (PyYAML).
- `read_registry()` returns the vendored compiled registry after checking its digest and version.
- The package ships the marker `py.typed`, and its type hints pass mypy in strict mode.
- The tests run every case of the JSON, number, Unicode, hash, HMAC, declaration and YAML corpora.
- `read_table()` reads a CSV file with the strict table reader of the [table specification](https://github.com/pablobernabeu/lmecheck/blob/main/docs/spec/tables.md), applying the table block of a declaration or inferring the column types without one, and raises `MixedcheckError` with one issue of the table area, located by byte offset. It returns a pandas DataFrame whose columns have dtype object, with the column types in `attrs["types"]`, and the tests run every case of the table corpus.
- `formula_ir()` parses an lme4-style formula with the in-house parser and builds the canonical IR of the [IR specification](https://github.com/pablobernabeu/lmecheck/blob/main/docs/spec/ir.md) from the formula, a declaration, the data, the coding argument, the weights and the sample columns, or raises `MixedcheckError` with one issue of the formula area. It reads a pandas DataFrame in which None, pandas.NA and the NaN of pandas' string dtype are missing, so that NaN in a float column is a value, and a categorical whose categories are strings by its labels, as R reads a factor. `canonical_hash()` of the IR gives its IR hash.
- `design_matrices()` builds the design and analysis samples of an IR as row positions counted from 0, X as a numpy array with the columns that the sequential rule drops, the sparse Z as a `scipy.sparse.csc_array` with its columns described in a DataFrame and the response, trials, offset and weight vectors, with the members and shapes of the R function. `design_samples()` returns the two samples alone, even when `design_matrices()` refuses the values of the rows.
- The tests run every case of the formula corpus, with the design matrices of the cases that give them, and the design and analysis samples of the table cases with a formula.
- `audit()` runs the checks of the registry on the design of a model in the steps of the [execution plan](https://github.com/pablobernabeu/lmecheck/blob/main/docs/design/03-execution-plan.md) (M2) and returns a `Results` object with the [results document](https://github.com/pablobernabeu/lmecheck/blob/main/docs/spec/documents.md) and its internal sidecar, whose printed form shows the banner of its privacy mode and one line for each finding. It takes the arguments of the R function, writes the access log with a keyed commitment to each outcome column read and commits to the analysis table, and the environment variable MIXEDCHECK_TIME fixes its times. `write_results()` writes the document as its canonical bytes and the sidecar with the results hash, and refuses file names that do not show which file may be shared (E7010).
- The exploratory check outcome.separation solves its linear programs with HiGHS through `scipy.optimize.linprog()` and names scipy with its version in `software.packages` of the results document whenever it runs, as the [registry entry](https://github.com/pablobernabeu/lmecheck/blob/main/spec/registry/checks/outcome.separation.yaml) states. It compares the objectives of the programs that give the coefficient bounds with the upper bounds of their multipliers and makes the finding near_threshold when a bound may lie further from the exact one than the parameter bound_tolerance allows, so that two clear findings of the R and Python packages give the same bounds within it.
- `new_commitment_key()` reads the time of MIXEDCHECK_TIME and gives E1312 when the operating system offers no secure source of random bytes, as the R function does.
- `design_matrices()` gives E6078 for events or trials of a response with a trials column that are not integers with 0 <= events <= trials, as the [IR specification](https://github.com/pablobernabeu/lmecheck/blob/main/docs/spec/ir.md) requires.
- The tests run every case of the audit corpus and compare the renderings of reals in messages with the vectors of the number corpus.
- `validate_results()` validates a results document, given as a file, as a value in memory or as a `Results` object, in the five stages of the [results specification](https://github.com/pablobernabeu/lmecheck/blob/main/docs/spec/documents.md) (Validation), shareable documents included, and verifies its internal sidecar: the results file hash, the keys that its commitments name and, with the data of the run as a CSV file or a DataFrame, every commitment to the data file, the analysis table and an outcome column. A document of another registry gives the warning W7090 as a `MixedcheckWarning`. The tests run every case of the results corpus and validate every document of the audit corpus with its data.
- The structural validator decides each condition of if once for each value and the conditions that hold only type, enum, const, not, required and properties without collecting issues, as the R package does, which makes the validation of results documents faster.
- In shareable mode, the default of `audit()`, the [privacy filter](https://github.com/pablobernabeu/lmecheck/blob/main/docs/spec/privacy.md) writes as null, with the reason privacy_suppressed and the rule that applied, the values that could disclose a person's data, suppresses as a whole a finding of an outcome check whose decision rests on a suppressed count, renders each message from the values written and replaces labels by pseudonyms, which the sidecar that `write_results()` writes maps back to them. It gives the documents and sidecars of the R package on every case of the audit corpus, on every table of the disclosure-attack harness and on the generated designs and edge cases of the differential test.
- `formula_ir()`, `design_matrices()` and `audit()` read a column of a pandas string dtype whose values are all missing as a string column, as R reads a character column of NA, where they read it as a boolean column.
- `pathology_zoo()` lists the fixtures of the [pathology zoo](https://github.com/pablobernabeu/lmecheck/blob/main/fixtures/zoo/README.md), small simulated data sets installed with the package, as a pandas DataFrame, or returns one of them as a dict with its data, the path of its installed data file, declaration, formula, the arguments of `audit()` for its run and its expected findings, after comparing each installed file with the MANIFEST.json of the package. The examples of `audit()`, `write_results()` and `validate_results()` audit fixtures of the zoo, and those of `validate_declaration()`, `read_table()`, `formula_ir()`, `design_samples()`, `design_matrices()` and `keyed_commitment()` read its fixture Z19N in place of data of their own.

### Changed

- The package requires scipy 1.15.3 or later, where it required 1.15, since `scipy.optimize.linprog()` takes time quadratic in the number of variables of a program before 1.15.3, which made outcome.separation take minutes from about 10,000 observations ([02-decisions.md](https://github.com/pablobernabeu/lmecheck/blob/main/docs/design/02-decisions.md), Q10).
- outcome.separation limits the size of its linear programs, the values other than 0 in the kept columns of the design sample times 10 more than their number, so that a categorical predictor with many levels no longer makes it take minutes. Above the parameter max_size, the check is not available with the reason too_large. Above max_bound_programs programs of bounds, or when their number times the size exceeds max_bound_size, the finding leaves out bounds and columns_involved and keeps its verdict, and a program whose dual has no verified solution is solved itself only up to the size max_primal_size ([registry entry](https://github.com/pablobernabeu/lmecheck/blob/main/spec/registry/checks/outcome.separation.yaml)).
- The compiled registry marks the counts of columns that give back the levels of an item, which the privacy filter suppresses with those levels ([privacy specification](https://github.com/pablobernabeu/lmecheck/blob/main/docs/spec/privacy.md), Across findings, rule 6), gives fallbacks to the messages of design.rank_deficiency that render them and drops dimension from the fallbacks of identifiability.levels_vs_dimension. A message that renders such a count needs a fallback (E4023), and gvif_per_df of design.collinearity is suppressed with df.
- The privacy filter matches the variables of a term to the items whose levels its counts of columns give back on the rows that those counts read, so that a grouping column that lacks a label in one row no longer lets the columns of a fixed term give back the levels that the filter hides. It hides the counts of columns of the IR when the levels of the table are hidden, and keeps those of a random term that '||' splits from a frozen factor, which has one column. The fallbacks of the messages budget of identifiability.df_budget and design_df of assignment.design_df no longer say that the levels are hidden.
- The privacy filter hides the analysed levels of a fixed factor beside design_df on rows of an assignment that hold the analysed rows or lie in them, suppresses a ratio whose numerator or denominator it suppresses whatever their class, hides the analysed levels of the disclosure unit with the analysed contributors and hides the analysed levels of an item of two members or more per level when the written rows or contributors would show how many lose every outcome, as the [privacy specification](https://github.com/pablobernabeu/lmecheck/blob/main/docs/spec/privacy.md) (step 5 of Steps and rule 1 of Across findings) states. `validate_results()` reports E7024 for a written ratio beside a suppressed count of any class.
- The privacy filter hides the analysed rows together with the analysed levels of an item none of whose levels holds two rows of the design sample, and with the analysed contributors when the disclosure unit is such an item, since each gives back the other, as the [privacy specification](https://github.com/pablobernabeu/lmecheck/blob/main/docs/spec/privacy.md) (rule 3 of Across findings) states. rank of identifiability.gram_rank is suppressed with smallest_eigenvalue, and the message not_identified falls back to a text without it.
- The statistic composite of structure.label_incidence is true only when the IR splits the units of one column of the pair: when the inner column of a pair declared nested, or either column of another pair, appears in no grouping factor without the other, as the [registry entry](https://github.com/pablobernabeu/lmecheck/blob/main/spec/registry/checks/structure.label_incidence.yaml) states. crossed_split and movers_split no longer fire for a model such as `(1 | subject) + (1 | item) + (1 | subject:item)`, in which each column keeps a random effect of its own.
- The privacy filter of `audit()` suppresses as a whole a finding of an outcome check that fails the minimum-count rule when its rows are fewer than min_count or when the written values of the findings on the same rows would leave its contributors a single value, and a finding on a grouping column whose labels are crossed with another column when one of its levels could be left with a single member by losing fewer than min_count rows. In the analysis sample, it suppresses a count other than 0 that is part of the hidden analysed levels of an item, such as constant_levels, levels_without_minority or all_zero_levels, when it would show that no level lacks every outcome, and events and non_events of a binary outcome beside hidden analysed rows, beside which the verdict of the separation check stays written, as the [privacy specification](https://github.com/pablobernabeu/lmecheck/blob/main/docs/spec/privacy.md) (Decisions, Across findings) states.
